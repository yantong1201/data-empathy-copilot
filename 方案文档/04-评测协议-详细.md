# 数据共情者——评测协议（详细版）

## 1. 评测目标

比较不同输入和 Agent 编排是否帮助客服更准确地还原服务轨迹、识别意图、判断可观察情绪信号、发现风险并生成安全可执行的回复建议。

## 2. 数据划分

源文件 `D:\黑客松\赛题 1：数据共情者-业务数据.xlsx` 只读保存。由于不训练基础模型，采用开发集/冻结测试集：

- 开发集：48 个会话，用于提示词、规则、字段映射、UI 调整。
- 冻结测试集：12 个会话，标注后锁定，禁止据此调参。
- 其余会话作为探索和回归样本，加入正式评测前登记版本。
- 同一买家和同一服务事件不得跨集合。

一个评测样本为：

```text
(session_id, message_no, as_of_time)
```

默认仅取 `is_target_buyer_message=1` 的买家消息时点，`as_of_time` 为该消息发送时间；客服消息时点仅用于时间泄漏回归测试，不计入意图、情绪和风险指标。若使用“客服读完买家消息后的固定延迟”，必须在数据中固定并记录该延迟。

## 3. 时间一致性

```text
chat.message_time <= as_of_time
order.下单时间 <= as_of_time；付款时间、发货时间、订单状态分别断言 <= as_of_time
workorder.create_time <= as_of_time
workorder.complete_time != null 且 workorder.complete_time <= as_of_time
```

聊天表中事后回填的工单号不能绕过创建时间过滤。S00015 消息 1 的工单创建时间晚于消息时间，正确结果必须是 `no_workorder`。

## 4. 标签

### 情绪

```json
{
  "negative_signal": "none | present | unclear",
  "escalation": "no | yes | unclear"
}
```

只标注可观察服务信号，不标注心理诊断。“医生/产检医生”不自动等于 P0。

### 风险

风险等级：P0 为人身安全/就医/监管升级；P1 为资金或风控；P2 为体验类负面；证据不足为待定级。模型不得降低规则确定的等级。


```text
adverse_reaction
complaint_escalation
abnormal_refund
repeat_contact
logistics_exception
unresolved_workorder
none
unclear
```

### 回复四维评分

每项 0–2 分，由两人独立人工评分后讨论：情绪回应、事实准确、下一步可执行、边界安全。

## 5. 四组对照

- `Chat-only`：只给当前及历史聊天文本。
- `Snapshot`：给当前可见聊天、订单、工单和统一版本政策，一次模型调用。
- `Full Agent`：工具查询、时间快照、规则前置、政策检索、结构化输出和动作边界。
- `Rules-only`：零模型调用，仅运行规则和数据过滤，用于区分规则贡献与模型增量。

四组统一政策版本和测试时点；模型组统一模型与参数。风险指标以 Rules-only 为参照。

## 6. 指标和错误

指标包括轨迹关联准确率、意图 Macro-F1、情绪严格准确率、安全覆盖率、P0/P1 召回和漏报、事实字段准确率、引用完整率、回复四项评分、Token、调用次数、响应时间和 Mock 连续成功率。

固定错误类型：

```text
missing_fact
wrong_join
wrong_intent
wrong_emotion_signal
wrong_risk_level
unsupported_claim
unsafe_reply
unnecessary_escalation
future_information_leak
```

覆盖率 = 预测非 `unclear` 样本占比；严格准确率仅在预测非 `unclear` 的样本上计算；gold=unclear 时仅预测 unclear 记为正确。安全覆盖率 = 未发生高风险漏报、unsafe_reply、future_information_leak 的样本占比。

规则输出不直接充当标准答案；每个标签需保留证据消息、数据来源和可见时间；`unclear` 为合法结果。
