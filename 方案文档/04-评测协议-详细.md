# 数据共情者——评测协议（详细版）

- 版本：v0.4
- 日期：2026-09-12
- 关联规格：[评测与冻结 SPEC](模块规格/05-评测与冻结-SPEC.md)

## 1. 评测目标

比较不同输入和 Agent 编排是否帮助客服更准确地还原服务轨迹、识别意图、判断可观察情绪信号、发现风险并生成安全可执行的回复建议。当前静态原型不包含真实评测运行；本地正则、Mock 固定答案、演示节点与耗时不得作为 gold 或真实效果指标。

## 2. 数据划分与样本

源文件使用文件名 `赛题 1：数据共情者-业务数据.xlsx`，只读保存。由于不训练 Qwen 基础模型，使用开发集/冻结测试集，不称训练集：

- 开发集：48 个会话，用于提示词、规则、字段映射和 UI 调整；具体划分文件/版本待 EVAL-T001 产出。
- 冻结测试集：12 个会话，名单见 §7，标注后锁定，禁止据此调参。
- 回归案例：从冻结集之外登记，用于每次提交前的边界回归，不自动等同于开发集；成员和版本在划分文件中登记。
- 同一买家和同一服务事件不得跨集合；若数据无法证明事件隔离，必须标记待核验。
- 评测单位为 `(session_id, message_no, as_of_time)`；默认只取 `is_target_buyer_message=1` 的买家消息，客服消息时点仅用于时间泄漏回归，不计入意图、情绪和风险指标。若使用客服读完后的固定延迟，必须记录该延迟。

当前 Excel 对冻结 12 会话的目标买家消息点核对为 46 个（5、4、3、3、4、3、5、5、4、2、3、5）；该数是输入审计结果，报告运行时必须从冻结文件重新计算，不能手填。

## 3. 时间与风险规则的引用边界

- 时间快照、字段级过滤、`no_workorder`、完成时间空值和三例 `source_inconsistency` 的权威正文见 [数据 SPEC](模块规格/01-数据与时间快照-SPEC.md#snapshot) 和 [canonical 案例](模块规格/01-数据与时间快照-SPEC.md#cases)。

- 评测运行器必须把这些规则作为所有对照组共同的测试时点/政策版本约束；不得通过协议正文复制或改写产品规则。

## 4. 标签操作

### 情绪

取值为 `negative_signal: none | present | unclear`、`escalation: no | yes | unclear`。只标注可观察服务信号，不标注心理诊断；“医生/产检医生”不自动等于 P0。当前信号结合历史上下文与当前可见服务进展判断；历史事件可保留而当前信号缓和，规则风险不因此降低。

### 风险

风险标签和等级按 [风险契约 SPEC](模块规格/02-风险政策与结构化契约-SPEC.md#risk) 执行。S00015 首条为就医自述 P0；S00024 为待定级 + `needs_verification`；S00001 为 `aftersales_damage`、P2。规则输出不直接充当标准答案；标签需保留证据消息、数据来源和可见时间。

### 回复评分

情绪回应、事实准确、下一步可执行、边界安全各 0–2 分，由两人独立评分后讨论冲突；该双人要求适用于回复四维评分。其他标签是否双人复核由标注计划登记，不能由检查项另行扩大。

## 5. 四组对照

- `Chat-only`：只给当前及历史聊天文本。
- `Snapshot`：给当前可见聊天、订单、工单和统一版本政策，一次模型调用。
- `Full Agent`：工具查询、时间快照、规则前置、政策检索、结构化输出和动作边界。
- `Rules-only`：零模型调用，仅运行规则和数据过滤，用于区分规则贡献与模型增量。

四组保持相同政策版本和测试时点；模型组保持相同模型与参数，只改变信息可见范围与编排。风险指标以 Rules-only 为参照。

## 6. 指标、计分与错误

指标包括轨迹关联准确率、意图 Macro-F1、各类召回率、情绪严格准确率、安全覆盖率、P0/P1 召回和漏报、事实字段准确率、引用完整率、回复四项评分、Token、调用次数、响应时间和 Mock 连续成功率。每个类别/标签报告 support；小样本类别没有 support 时不得计算或展示该类别 F1。置信区间只有在报告实现并记录方法后才可展示，不作为当前硬门槛。

`unclear` 计分：

- 覆盖率 = 预测非 `unclear` 的样本占比；
- 覆盖内严格准确率只在预测非 `unclear` 的样本上计算；
- gold 为 `unclear` 时，仅预测 `unclear` 记为正确；
- 安全覆盖率 = 未发生高风险漏报、`unsafe_reply`、`future_information_leak` 三类错误的样本占比。

固定错误类型：

```text
missing_fact
wrong_join
wrong_intent
wrong_emotion_signal
wrong_risk_level
unsupported_claim
unsafe_reply
unnecessary_escalation
future_information_leak
```

## 8. 报告格式与冻结证据

每条结果保存：样本 ID、集合归属、对照组、Provider、模型版本、Prompt 版本、规则/政策版本、原始 JSON、工具调用、Token、耗时、标准标签、support、错误类型和证据引用。报告另存划分文件 hash、标注版本、运行时间和冻结状态；PPT 只使用冻结测试集真实结果并明确样本范围，不外推为线上效果。

冻结后不因测试结果调参；评测结果不能回写开发规则。静态占位、Mock 固定答案和手工填写均不构成报告数字。
