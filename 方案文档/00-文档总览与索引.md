# 数据共情者文档总览与索引

- 版本：v0.2
- 日期：2026-09-13
- 状态：文档重组完成；工程实现仍以各任务状态和证据为准。

## 推荐阅读路径

1. 先读本页，了解模块、阶段、权威来源和当前接续点。
2. 读 [01-方案规格-SPEC.md](01-方案规格-SPEC.md) 了解产品定义、全局边界、核心流程和跨模块约束。
3. 按要接手的模块读 `模块规格/`，再读对应 `模块任务/` 和 `模块验收/`。
4. 按当前交付阶段读 `阶段计划/`；阶段退出条件链接到模块检查项。
5. 展示或评测时再读 [03-方案冻结版-详细.md](03-方案冻结版-详细.md)、[04-评测协议-详细.md](04-评测协议-详细.md)、[05-三分钟Demo脚本-详细.md](05-三分钟Demo脚本-详细.md)。
6. [06-方案审查报告.md](06-方案审查报告.md) 仅作历史审查记录，不是规则来源。

## 权威来源与替代关系

| 事实类别 | 唯一维护位置 | 其他文档的职责 |
|---|---|---|
| 产品定义、全局边界、跨模块约束 | [01-方案规格-SPEC.md](01-方案规格-SPEC.md) | 模块规格只补充本模块接口和任务引用 |
| 阶段顺序、依赖、阶段门槛 | [02-实施计划-PLAN.md](02-实施计划-PLAN.md) 与 `阶段计划/` | 任务/检查项提供可追溯执行证据 |
| 数据加载、关联、时间快照 | `模块规格/01-数据与时间快照-SPEC.md` | 总 SPEC 只保留入口和跨模块引用 |
| 风险、政策、Provider JSON 契约 | `模块规格/02-风险政策与结构化契约-SPEC.md` 与同目录正式 `SCHEMA.json` | 评测、Agent、UI 通过 ID 引用 |
| 工作台交互和草稿 | `模块规格/04-客服工作台与证据交互-SPEC.md` | Demo 脚本引用交互基线 |
| 数据划分、标注、指标、报告 | [04-评测协议-详细.md](04-评测协议-详细.md) | `模块规格/05-评测与冻结-SPEC.md` 只规定交付接口和引用关系 |
| 演示、运行说明、提交物料 | `模块规格/06-演示运行与提交-SPEC.md` | Demo 脚本保留叙事正文 |

旧文档不删除。迁移后的原章节以入口、摘要或引用为主，避免与模块规格形成第二套正文。

## 模块关系

```text
数据与时间快照 → 风险/契约 → Agent/Provider → 工作台
        └──────────────→ 评测与冻结 ──────────────→ 演示/提交
```

## 当前状态与接续点（事实状态）

当前代码只有 `prototype/index.html`：三案例硬编码的静态交互基线已有；未发现真实数据加载器、后端、Provider、Schema 校验器、冻结评测运行器或自动测试产物。静态页显示的工具节点、耗时和评测入口不能作为真实交付证据。当前从 **阶段 A** 开始，优先完成 `DATA-T001`–`DATA-T004`，再进入 B。

| 状态词 | 使用含义 |
|---|---|
| 已有静态基线 | 代码或材料中可直接核对，但不等于真实模块交付 |
| 待实现 | 规格已定，尚无代码/产物 |
| 待验证 | 已有候选实现或材料，但本轮没有对应运行证据 |
| 后续扩展 | 核心早鸟门槛通过后再做，不进入当前主线门槛 |
