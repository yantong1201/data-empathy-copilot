- 版本：v0.2
- 日期：2026-09-12
- 迁移来源：旧 SPEC §6、旧 PLAN 阶段 A。
- 接续：[数据任务](../模块任务/01-数据与时间快照-TASKS.md) → [数据验收](../模块验收/01-数据与时间快照-CHECKLIST.md)。

## 职责与输入输出

输入为官方 Excel 只读文件、会话/消息选择和 `as_of_time`；输出为字段映射、可复现快照、来源引用、关联命中和自检报告。本模块不做意图、情绪、风险定级、模型调用或外部动作。

## 已核对输入

源文件名为 `赛题 1：数据共情者-业务数据.xlsx`，全部为虚构 MOCK 数据：聊天 998 行/138 会话/112 买家；订单 113 条；补发换货 24、线下打款 13、物流 15、不良反应 10、售后退货 18，共 80 条工单；聊天有 29 条图片消息和 `image_path`，业务图片文件不存在。

表名和关键字段：聊天记录含 `会话ID`、`消息序号`、`发送时间`、`角色`、`买家昵称`、`is_target_buyer_message`、`message_text`、`内容类型`、`image_path`、关联订单/工单号；订单含订单号、会话ID、买家昵称、状态、下单/付款/发货时间；五类工单含工单号、会话ID、关联订单号、状态、创建/完成时间。数据说明写明：一个会话至多一笔订单、至多一张工单，工单挂在来源订单上；这是本次比赛输入的已核验性质，不直接泛化为生产系统规律。

## 关联与快照契约

<a id="snapshot"></a>

- 主键按字符串读取：`session_id`、`message_id`、`order_id`、`workorder_id`、买家标识和订单/工单号禁止浮点化。
- 精确关联优先按会话 ID；聊天事后回填的关联订单号/工单号可作潜在关联键并按记录交叉校验，不能绕过时间过滤。向量检索仅用于政策、产品说明和话术，不用于业务事实关联。
- `chat.message_time <= as_of_time`。
- 订单仅在下单时间 `<= as_of_time` 时可见；付款、发货、订单状态分别按对应字段时间断言。订单缺少状态生效时间时，不把“交易成功”等状态直接当作快照事实，返回未知或待核验。
- `workorder.create_time <= as_of_time`；创建前返回 `no_workorder`。
- 只有 `complete_time != null && complete_time <= as_of_time` 才显示完结状态和完成时间；完成时间为空时不能显示完结。
- 当前客服声称已建单而系统暂无记录时，保留客服原句与“工单系统暂无记录”，标记 `source_inconsistency`；不提前暴露未来工单号、字段或时间。

数据接口实现需要自检：表名、行数、主键唯一性、字段空值、时间可解析性/单调性、每会话订单/工单唯一性、非空关联键命中率。审计报告中的订单非空关联键命中为 819/819，工单非空关联键命中为 629/629；这些数字是输入核对证据，不代表时间快照已实现。
