# 模块规格：客服工作台、证据交互与草稿

- 版本：v0.6
- 日期：2026-09-13
- 迁移来源：旧 SPEC v0.4 §3.1–3.4、旧 PLAN 阶段 D。
- 接续：[任务](../模块任务/04-客服工作台与证据交互-TASKS.md) → [验收](../模块验收/04-客服工作台与证据交互-CHECKLIST.md)。

## 职责与输入输出

人工客服用左侧会话队列、中部聊天与编辑区、右侧 Copilot 定位事实并处理下一步；主管查看风险与处置状态。
输入为可见快照、[分析 JSON](02-风险政策与结构化契约-SPEC.md#json)、来源引用和真实运行记录；输出为时点选择、按快照隔离的编辑草稿、人工确认结果和处置记录。UI 不自行补未来事实或调用真实业务动作。

<a id="interaction"></a>
## 已确认交互基线

本节是从 HTML 原型承接到工程实现的交互要求；原型仅部分实现，具体限制见下文，浏览器回归和真实数据/Agent 接入仍待验证。不能因为原型缺少确认或日志而省略工程要求。

信息量丰富不等于效率提升。首屏优先支持当前判断、下一步处理和最多 3 条关键依据；完整工具请求/响应、why/why-not、安全校验明细和处置日志按需展开，不新增常驻信息卡。新增展示必须能说明减少了哪一步判断、查找或操作；仅字段齐全不作为效率提升证据。

- 左栏展示会话 ID、昵称、场景、风险、处置状态及筛选；中栏显示按时间排列的买家/客服消息、图片类型、路径与分析状态。
- 首次访问会话从首条买家消息开始；本次页面访问内返回会话恢复上次消息或工单快照。上一条、下一条、滑条、回到首条、点击可见消息均可选时点。
- 保留“当前消息 / 工单创建后 / 工单完成后”三个回放快捷入口：当前消息取所选消息时间，后两项分别取已选案例工单的创建/完成时间作为 `as_of_time`，按统一快照契约重算，不直接设置业务状态；对应时间为空时禁用入口并说明原因。这些按钮是回放导航，目标时点的工单字段只在用户主动切换后可见；证据定位不触发跳转。
- 切会话关闭详情抽屉并恢复“处理建议”页。右栏顶部保留当前判断、风险、历史投诉/升级、来源冲突和变化提示；关键风险/冲突不能随详情折叠而消失。
- 默认“处理建议”显示下一步、待核验字段、回复预览、最多 3 条关键依据。“分析详情”含完整来源、服务轨迹、事实/风险和 8 个工具节点。底部固定“填入回复、工单草稿、人工升级”。
- 点击工具节点按需打开详情抽屉，展示工具名称、请求 JSON、响应摘要、来源引用和本次 `as_of_time`；引用仍可定位，查看/关闭抽屉不改变时点、处置状态或编辑草稿。请求与响应必须对应同一次运行；真实耗时/Provider/降级信息来自运行记录，无记录时标记待接入，不把固定演示值显示为实测值。
- 点击关键依据、历史提示或冲突引用展开完整来源；聊天来源高亮对应气泡并保持当前 ``as_of_time``。只有主动选择消息/快照才改变分析时点。
- 右栏预览、中栏编辑；手工回复按会话和时点隔离，切回可恢复。“填入回复”确认后用建议替换编辑框；“使用此回复”确认后保留当前编辑内容，不发送。
- 回复草稿不得重复询问当前快照已经可见且已能关联当前诉求的订单号、运单号或工单号；缺少可见关联或关联仍不确定时，才可将其列为待核验字段。
- 历史投诉/升级提示若被用于草稿，应引用当前时点可见的原句或来源引用；当前信号缓和时可降低当前情绪展示，但不得降低规则确定的高风险。
“工单草稿/人工升级”独立按钮经确认展示相应本地草稿。生成草稿不等于提交工单、完成升级或风险解决，不改写业务快照；“人工升级”由 UI 基于当前分析生成 `escalation_draft`，不新增第 9 个 Agent 工具，也不调用真实升级接口。

<a id="queue"></a>
## 队列与状态（待实现部分）

目标沿用 ``open/watching/resolved`` 处置状态，补齐场景、处置状态筛选与跟踪记录。当前静态搜索支持昵称、会话 ID、订单号、工单号及预览；风险筛选仅全部/P0/P1，“待跟进”按案例固定。新加状态选择器仅保存页面内存中的选择，没有确认流程、处置日志或队列筛选联动，不能作为完整状态管理的交付证据。

搜索命中只用于定位会话，不能证明回填工单号当时已可见；进入结果按该会话首条或本次访问保存的时点加载，仍执行 [数据快照契约](01-数据与时间快照-SPEC.md#snapshot)，不得因搜索命中跳到未来工单快照或展示未来字段。

处置状态入口放在现有“当前判断”卡内，使用紧凑控件，对应“处理中 / 持续跟进 / 已解决”，不另建首屏状态面板。选择新状态后由人工确认才写入，取消保持原状态；状态变化不能降低规则风险或改写业务快照。详细操作者、时间、分析依据及前后状态从该入口按需打开抽屉查看，不常驻首屏；未发生处置时显示空记录，不伪造历史。

UI-T003 负责处置流程和操作记录，状态机沿用本节已定义的允许转移和 ``resolved`` 条件；所有转移由人工确认触发，生成草稿不视为已处理。风险候选状态 ``needs_verification`` 与队列处置状态用途不同，不能混作同一字段。

处置记录至少保存操作者、操作时间、所基于的分析标识/时点、操作类型（确认、改稿、拒绝）和状态变更前后值；人工操作不自动证明风险已解决。右栏“变化提示”只突出有快照依据且会影响下一步处理的变化，如工单可见性、来源冲突或风险变化；不因草稿措辞变化显示泛化的“处理建议更新”，不能以提示数量证明效率提升。

处置状态允许转移：``open → watching``（人工确认已开始跟进或仍需补证）、``watching → watching``（补充处置记录）、``watching → resolved``（人工确认当前风险已处理且没有未完成的必需动作）、``open → resolved``（仅适用于人工确认无需继续跟进的低风险事项）。``resolved`` 不能由生成草稿、改稿或单纯查看证据触发；规则确定的 P0/P1、未完成的必需工单动作或仍有关键来源冲突时不得自动转为 ``resolved``。取消状态变更不写入新状态，但可记录取消操作。

处置日志与分析运行通过 ``analysis_id`` 关联，并同时保存 ``session_id``、``as_of_time``、操作者、操作时间、操作类型和前后状态。工作台只接受 ``safety_check_result.status=pass`` 的分析作为人工确认依据；校验失败或未运行时，详情按需显示失败/待接入原因，不能伪造通过。

人工确认必须携带当前 `analysis_id`、`as_of_time`、草稿 `revision`/`draft_hash` 和幂等 `operation_id`。服务端或状态管理层需校验这些值仍对应当前会话、当前快照和当前草稿；异步返回的旧分析、旧时点或旧草稿一律拒绝确认并要求重新分析/确认。拒绝不改变业务快照和队列状态，并记录拒绝原因。

<a id="status"></a>
## 当前限制与工程接入

- 静态页面为三案例硬编码，无 Excel 加载器。工具是本地请求/响应示意，JSON 校验器、Provider 切换和真实统计尚未接入；“评测”入口只是待接入提示。
- 三个回放快捷按钮已有；缺少完成时间时当前代码只在点击后提示并拒绝切换，尚未达到入口禁用的目标要求。
- 顶部已有静态 Mock 与待接入说明；工程目标为显示案例、时点、Provider、在线/Mock、Token、响应时间、调用数和降级原因。真实统计需由 Agent 记录提供，不能称为当前已实现。
- 会话快照/手工回复仅页面内存；刷新或关闭后丢失，工单/升级草稿仅抽屉展示，无持久保存和操作日志。跨刷新恢复属于后续工程项，不新增早鸟门槛。
- 近期情绪仍主要是末条买家文本正则，历史提示独立展示；尚不满足 [完整上下文情绪规格](02-风险政策与结构化契约-SPEC.md#emotion)，不能验收情绪效果。
- 无真实图片文件；展示路径及缺失状态，视觉分析仍为扩展。

<a id="acceptance"></a>
## 验收边界

最终工程无静态摆设按钮；右栏不能遮挡聊天，关键状态有文字、不仅靠颜色。人工确认按 [动作边界](02-风险政策与结构化契约-SPEC.md#confirmation)。静态浏览器交互回归和真实快照/Provider 联调分别留证，静态通过不能替代工程通过；细项见 UI-C001–UI-C004。
