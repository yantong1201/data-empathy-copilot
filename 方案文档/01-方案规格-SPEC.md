# SPEC：数据共情者——客服辅助 Copilot

- 状态：产品基线；详细模块规格见本页链接。

## 1. 产品定义与边界

本产品嵌入人工客服工作台右侧，按当前消息时点融合聊天、订单、订单物流字段和售后/物流工单，输出带证据的事实、意图、可观察情绪信号、风险判断、可编辑回复草稿和下一步建议。它不是面向消费者的自动客服；发送、升级、建单、退款、赔偿、线下打款必须人工确认。

价值表述：帮助客服更快定位事实、更稳判断风险、更有边界地处理下一步。

## 2. 赛题对齐与核心流程

覆盖官方要求的智能接待辅助插件和风险预警跟踪看板；多模态是扩展，不是核心评分依赖。固定流程：

```text
打开会话 → 选择 as_of_time → 查询可见聊天/订单/工单
→ 服务时间线 → 规则风险 → 必要时政策 → Agent 结构化分析
→ 证据/风险/边界校验 → 人工编辑并确认草稿 → 风险跟踪
```

官方客服工作台目标区域是右侧辅助区；左侧客户/接待管理、中部聊天与商品卡为既有布局约束。详细模块接口见 [数据 SPEC](模块规格/01-数据与时间快照-SPEC.md)、[风险/契约 SPEC](模块规格/02-风险政策与结构化契约-SPEC.md)、[Agent SPEC](模块规格/03-Agent与Provider-SPEC.md)、[工作台 SPEC](模块规格/04-客服工作台与证据交互-SPEC.md)。

## 3. 全局不可改变的规则

- 每次分析必须带 `as_of_time`；数据可见性和源冲突规则唯一维护于数据模块规格。
- 情绪只用 `negative_signal` 和 `escalation` 两枚可观察信号；风险由规则确定，模型不得降级；等级定义唯一维护于风险/契约模块规格。
- 使用一个主 Agent 加结构化工具；Provider 至少 `QwenProvider`、`MockProvider`、`RuleProvider`，共用 JSON 契约，Qwen 失败须降级。
- 工具只能读取或生成草稿；所有不可逆业务动作人工确认。
- 评测使用 48 个开发会话、12 个冻结会话、四组对照；`unclear` 同时报告覆盖率和覆盖内严格准确率。详细口径唯一维护于 [评测协议](04-评测协议-详细.md)。

## 4. 主案例和当前原型事实

S00015 用于就医/不良反应 P0、时点和来源冲突；S00024 用于异常仅退款待核实，不得断言欺诈或自动 P1；S00001 用于商品到手破损售后 P2，不归因物流。案例夹具的精确时间和证据由数据模块维护。

当前 `prototype/index.html` 只有三案例硬编码静态交互：已有回放、证据联动、页面内草稿和确认按钮；没有 Excel 运行加载、真实 Agent/Provider、Schema 校验、处置状态管理或冻结集真实评测。不得把静态节点、固定耗时或评测占位当作交付证据。

## 5. 早鸟核心门槛

三主案例稳定运行；Mock 无网无密钥连续可用；Qwen 失败自动降级；评测一键输出四组真实结果；时间泄漏测试通过；高风险、发送和资金动作需确认；无事实编造、医学诊断或无依据定责；能从会话走到证据、回复草稿、工单草稿和风险跟踪。门槛按阶段检查项追溯，不在总 SPEC 重复维护。
