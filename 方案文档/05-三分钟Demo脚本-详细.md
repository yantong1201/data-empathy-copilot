# 数据共情者——三分钟 Demo 脚本（详细版）

- 版本：v0.5
- 日期：2026-09-13

## 目标

用三个案例在三分钟内展示：系统能看清事实、跟上服务进展、判准风险，并保留人工控制。

本脚本描述完整交付的演示目标。当前 `prototype/index.html` 仅为三案例硬编码的静态 UI 演示；讲解须明确真实 Agent、Provider 降级、评测和风险跟踪尚待实现，不能把演示节点、耗时或评测占位卡当作验收证据。

当前原型按 模块规格/04-客服工作台与证据交互-SPEC.md 回放：首次访问会话在首条，返回已访问会话会恢复上次快照，因此每段开始前点击“回到首条”。右栏默认展示处理建议；点证据只定位来源，点消息才改变分析时点。手工回复仅在本次页面访问内按快照保留，刷新会丢失。以下时间分配为脚本目标，尚非计时验证结果。

## 0:00–0:15 开场

画面：三栏工作台全屏；使用当前静态稿时，开场明确说明“这是三案例静态交互演示，分析为本地演示逻辑”。

讲解：

> 这是给人工客服使用的右侧 Copilot。它把截止当前时点的聊天、订单和工单串起来，给出带证据的判断、回复草稿和下一步动作，不自动代替客服发送或执行资金动作。

## 0:15–1:20 S00015：不良反应和就医升级

1. 选择 S00015，点击“回到首条”。
2. 指出当前 `as_of_time` 和“暂无可见工单”。
3. 说明聊天行虽然有工单号，但工单实际 `17:13:33` 才创建，当前不能提前显示。
4. 指出首条已有“我人现在在医院”的自述，当前已触发 P0；工单“是否就医”字段尚不可见。
5. 逐条推进，展示原句证据、缺失字段与服务进展；情绪缓和后历史就医风险仍为 P0，工单创建前的冲突提示不得泄漏未来工单时间。
6. 点击“填入回复”并确认，在中栏修改一处措辞；独立点击“工单草稿”并确认，查看本地草稿，不将其说成工单已经创建。
7. 强调升级和发送都需人工确认。

## 1:20–2:10 S00024：空包裹和异常仅退款

1. 切换 S00024，点击“回到首条”。
2. 指出当前只有用户自述，没有图片、称重和出库证据。
3. 指出售后工单尚未创建，不能显示“是否异常=是”或最终状态。
4. 展示“异常仅退款 / 待核实”、`待定级`和缺失字段；切至创建后展示“是否异常=是”“退货原因=仅退款-空包裹(待核实)”与“处理中”，说明这些是登记而非核实结果，不自动定 P1。
5. 生成建议：保留外箱和面单、补六面照片、查询出库与揽收重量。
6. 点击“填入回复”并确认；若演示“使用此回复”，说明它仅保留当前编辑内容。需要查看工单草稿时独立点击“工单草稿”并确认，不触发退款或更新业务工单。

可说：

> 这里既承认用户着急，也把事实和待核实分开，避免机械拒绝和无依据定性。

## 2:10–2:45 S00001：泵头破损和换货

1. 切换 S00001，点击“回到首条”，推进至第 3 条图片消息。
2. 展示破损换货意图、订单事实、图片消息状态和换货草稿；类型为商品到手破损售后（`aftersales_damage`）、P2，不归因物流。
3. 说明官方 Excel 当前没有真实图片文件，因此视觉分析是可插拔扩展，文字和结构化数据主流程不受影响。

## 2:45–3:00 评测收束

打开评测摘要，展示 Chat-only、Snapshot、Full Agent、Rules-only 四组对照，并指出重点指标：高风险召回、事实准确、待核实识别、未来信息泄漏、Token 和响应时间。

仅在冻结测试集真实运行并生成报告后执行该段；当前静态稿只能说明评测计划与尚未验证的缺口，不展示虚构数字，也不以占位摘要宣称达标。

当前静态稿的收束：保留工作台画面，说明后续将运行四组对照；无需点击只弹“待接入”提示的评测入口，不宣称已打开评测报告。

收束词：

> 我们衡量的不是模型说得多像人，而是它能否在正确时间看到正确事实，给客服一个安全、可解释、可执行的下一步建议。

## 演示前检查

以下为完整交付检查项；静态页回放通过不能代替真实 Provider 降级和冻结集评测验收。

- [ ] Qwen 配置失败自动降级并显示原因。
- [ ] 首条消息不会显示未来工单和未来完成状态。
- [ ] S00024 不会被断言为空包裹或欺诈已证实。
- [ ] S00015 高风险动作需要人工确认。
- [ ] 所有回复可编辑，发送不调用真实外部系统。

- [ ] 评测数字来自冻结测试集真实运行。
