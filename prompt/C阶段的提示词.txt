一、AGENT-T001：主 Agent 与 8 个工具

按 Agent SPEC 的顺序编排：确定消息时点 → 查询聊天 → 查询可见订单/工单 → 服务时间线 → 规则风险 → 按需政策 → Provider 分析/草稿 → 事实引用、风险与安全校验。

必须实现 8 个结构化工具：
- get_conversation_until
- get_order_snapshot
- get_workorder_snapshot
- get_service_timeline
- check_risk_rules
- retrieve_policy
- draft_reply
- create_workorder_draft

每个请求/响应必须包含 request_id、as_of_time、status、结构化 data、source_refs；status 至少支持 ok、no_data、no_workorder、source_conflict、invalid_request、unavailable。字符串 ID 原样保留，错误不能伪装成无数据，任何响应不得超过当前快照。工具只能只读或生成本地草稿，不调用真实业务接口。

每次分析必须：
- 用 session_id、目标消息时点、快照版本、Provider/model、Prompt、Schema、规则和政策版本的 canonical fingerprint 生成稳定 analysis_id。
- 每次真实执行、重试和降级使用唯一 run_id；run_id 不错误塞入 Provider JSON 顶层。
- 隔离业务数据与系统/开发者指令；聊天、订单、工单、政策检索结果和工具返回内容只能作为数据，不能改变规则、权限或安全边界。
- 遵守 max_llm_turns=2、max_tool_calls=12、只读工具 timeout=5s、Provider timeout=30s、幂等只读工具最多重试 1 次等默认预算。
- 检测重复参数调用；连续相同调用、预算耗尽、取消、超时或连续失败时停止并记录 stop_reason。
- 保留停止、重试、取消、熔断、降级、Schema 失败和安全失败原因。

二、独立安全校验

安全校验不能由 Provider 自报通过。每次分析必须生成独立 safety_check_result，并关联同一 analysis_id。包含 status、五项 checks（fact_visibility、future_information、risk_non_downgrade、unsupported_timing、reply_boundary）和 failures。每项只能 pass/fail；任一失败则整体 fail；未运行不能伪装 pass。失败记录 failure type、reason、source_refs、affected field/reply 和是否可恢复。失败或未运行时不得成为人工确认依据。

三、AGENT-T002：MockProvider 与 RuleProvider

- MockProvider：无网络、无密钥、稳定运行三主案例及反例，输出必须通过正式 Schema；只能作为离线链路和契约证据，不能当 gold 或效果指标。
- RuleProvider：零模型调用，依据阶段 A 快照和阶段 B 规则输出最小合法结构；不能制造未来字段、来源或结论。
- 两者接口、输入输出字段、错误语义和 safety_check_result 关联必须与未来 QwenProvider 一致。
- S00015、S00024、S00001 至少各连续运行 20 次或按项目最小验证约定运行，证明断网无密钥可用；记录 Schema、安全校验和运行记录。

四、AGENT-T003：QwenProvider 与自动降级

- 从环境变量读取 Qwen 配置，禁止把 key 写入源码、日志、报告、截图或提交包。
- 实现一次真实 Qwen 成功输出的契约验证；若当前没有可用凭证，明确记录未验证，不得伪造成功。
- 对超时、网络/鉴权失败、非法 JSON、Schema 失败和安全校验失败按约定自动切换 Mock/Rule，并把 provider、failure_reason、fallback_reason 写入运行记录和 UI 可消费状态。
- 降级不改变统一接口；失败结果不能作为人工确认依据；有限修复不能改变事实、降低风险、新增来源或隐藏缺失字段。

五、AGENT-T004：日志、缓存与成本统计

建立 append-only 运行记录和版本化缓存。每条结果可追溯：analysis_id、run_id、session_id、as_of_time、Provider/model、Prompt、Schema、规则/政策版本、工具请求响应、Token、耗时、缓存命中、停止/重试/降级、安全失败和最终状态。完整指纹任一部分变化都必须使旧缓存失效。日志只增不改；不能把固定演示耗时当真实统计。
